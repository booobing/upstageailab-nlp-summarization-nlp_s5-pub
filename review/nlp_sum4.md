# NLP 요약 모델 개발 과정 정리 - Part 4

## 1. SpellChecker 관련 이슈
### 문제점
- SpellChecker 사용 시 처리 속도가 매우 느림
- 각 단어마다 사전 대조, 교정 후보 생성, Levenshtein 거리 계산 등 CPU 집약적 작업 필요

### 해결 방안
- SpellChecker 제거하고 기본적인 텍스트 정제만 수행
- pandas의 벡터화 연산 사용으로 처리 속도 향상
- 정규식을 사용한 효율적인 공백 처리

## 2. 프롬프트 엔지니어링
### KoBART 모델에 프롬프트 적용
- 특수 토큰을 사용한 프롬프트 구현
  ```python
  special_tokens_dict = {
      'additional_special_tokens': ['[요약]']
  }
  ```
- 간단한 프롬프트 템플릿 설계
  ```python
  "template": "[요약]{dialogue}"
  ```

### 프롬프트 최적화
- max_length vs 프롬프트 길이 trade-off
- 프롬프트를 최소화하여 실제 입력 텍스트를 위한 공간 확보
- GPU 메모리 효율성과 처리 속도 고려

## 3. 데이터셋 처리 개선
### 프롬프트 적용 범위
- 학습 데이터: 프롬프트 적용
- 검증 데이터: 학습 데이터와 동일한 형식 유지를 위해 프롬프트 적용
- 테스트 데이터: 추론 시 동일한 조건 위해 프롬프트 적용

### 데이터 정제 이슈
- Solar API 응답으로 인한 'i:' 패턴 발생
- 정규식을 사용한 패턴 제거 구현
  ```python
  df['dialogue'] = df['dialogue'].str.replace(r'^i:\s*', '', regex=True)
  df['summary'] = df['summary'].str.replace(r'^i:\s*', '', regex=True)
  ```

## 4. 시행착오 및 교훈
1. **데이터 일관성**
   - 학습/검증/테스트 데이터의 형식 통일 중요성
   - 프롬프트 적용이 모든 단계에서 필요

2. **성능과 효율성**
   - SpellChecker 제거로 처리 속도 개선
   - 프롬프트 길이 최소화로 메모리 효율성 확보

3. **데이터 정제**
   - API 응답 형식으로 인한 예상치 못한 패턴 발생
   - 벡터화 연산을 통한 효율적인 데이터 처리

## 5. 향후 개선 방향
1. 더 효율적인 텍스트 정제 방법 연구
2. 프롬프트 엔지니어링 최적화
3. 데이터 처리 파이프라인 안정성 향상
