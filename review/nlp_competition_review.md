# 자연어 처리 경진대회 후기 및 학습 기록

## 1. 프로젝트 개요

이번 자연어 처리 경진대회는 혼자서 진행하게 되었습니다. 사실 처음에는 2인 1팀으로 시작했지만, 대회가 시작되자마자 팀원이 연락이 되지 않아 혼자 진행하게 되었습니다. 하지만 이전 CV 경진대회에서의 경험을 통해, 오히려 혼자 진행하는 것이 제 성향에 맞다고 판단했습니다. 

팀 프로젝트에서는 협업과 개인 작업의 경계가 모호해져 방향성을 잃기 쉬웠던 반면, 혼자서는 주도적으로 다양한 시도를 할 수 있었기 때문입니다. 물론 분업이 불가능해 시간적 여유는 부족했지만, 제가 하고 싶은 실험들을 마음껏 시도해볼 수 있어서 오히려 더 재미있게 프로젝트를 진행할 수 있었습니다.

이 프로젝트의 주요 목표는 대화 데이터를 요약하는 모델을 설계하고 성능을 극대화하는 것이었습니다. 이를 위해 KoBART, Solar LLM, 강화 학습(PPO) 등 다양한 기술을 시도해보았고, 데이터 전처리부터 프롬프트 엔지니어링, 하이퍼파라미터 최적화까지 폭넓은 실험을 진행했습니다.

## 2. 개발 과정

### 2.1 초기 모델 설계 및 베이스라인 구축

#### 개요
- **목표**: KoBART 기반 대화 요약 모델 설계 및 초기 성능 평가
- **평가 지표**: ROUGE 점수를 사용하여 요약 성능 검증

#### 진행
- **첫 번째 제출(48.1088)**: 베이스라인 모델을 구축하고 기본 전처리를 통해 안정적인 초기 성능 확보
- **일곱 번째 제출(47.6577)**: 원본 코드를 재실험하며 성능 비교 및 최적화 방향성을 탐색

#### 학습점
- 베이스라인 모델은 이후 실험과 비교를 위한 중요한 기준점이 되었으며, 단순하고 명확한 접근법의 중요성을 확인했습니다.
- 베이스라인 설정이 모델 개선의 출발점이자 성능 비교의 기준으로 기능하며, 이후 실험 방향 설정에 결정적인 역할을 했습니다.

### 2.2 데이터 전처리 및 품질 개선

#### 개요
- **목표**: 데이터 품질 향상을 통해 모델 성능 극대화

#### 진행
- **세 번째 제출(40.1358)**: 데이터 노이즈 제거, 유사어 교체, 긴 대화 처리 등 다양한 전처리 기법 적용
- **네 번째 제출(28.1606)**: Korean Sentence Splitter 모델 추가 및 파라미터 최적화를 시도했으나 성능 하락
- **다섯 번째 ~ 여섯 번째 제출(최고점: 28.9317)**: Simple 모델 기반 전처리 실험

#### 학습점
- 데이터 전처리의 품질이 모델 성능에 미치는 영향을 체계적으로 분석하며, 효율적인 데이터 처리와 API 호출 최적화의 중요성을 확인했습니다.
- API 호출 속도 문제를 해결하기 위해 병렬 처리 및 로컬 처리를 도입하며, 데이터 증강이 항상 성능 개선으로 이어지지 않음을 경험했습니다.

### 2.3 프롬프트 엔지니어링

#### 개요
- **목표**: 입력 데이터 형식을 최적화하여 요약 성능을 극대화

#### 진행
- **여덟 번째 제출(42.3530)**: 정서적 표현 제거 및 객관적 요약 중심의 프롬프트 설계
- **열 번째 제출(42.9535)**: 배경 정보와 맥락을 추가하여 요약 품질 개선
- **열아홉 번째 ~ 스물세 번째 제출(최고점: 44.5761)**: Solar Pro 모델과 프롬프트를 최적화하여 성능 극대화

#### 학습점
- 프롬프트 설계는 입력 데이터를 단순히 정제하는 것을 넘어 모델의 성능을 근본적으로 개선할 수 있는 중요한 요소임을 확인했습니다.
- 다양한 프롬프트 구성 방식을 실험하며, 요약의 목적과 데이터 구조에 맞는 프롬프트 설계가 성능 향상에 결정적인 역할을 했습니다.

### 2.4 강화 학습(PPO) 적용

#### 개요
- **목표**: 강화 학습 알고리즘을 활용하여 모델의 성능을 지속적으로 개선

#### 진행
- ROUGE 점수를 보상으로 설정하여 과적합을 허용하며 PPO 알고리즘 최적화
- Temperature와 top_p 값을 조정하며 성능 미세 조정

#### 결과
- **스물세 번째 제출(44.5347)**: 강화 학습의 효과로 안정적이고 높은 성능 확보

#### 학습점
- 강화 학습은 정적인 학습 방식에서 벗어나 동적인 최적화를 가능하게 했으며, 학습 안정성과 하이퍼파라미터 조정의 중요성을 실감했습니다.
- PPO의 하이퍼파라미터 조정 및 안정적인 학습 환경 구축이 성능 개선에 핵심적인 역할을 했습니다.

## 3. 시행착오와 해결 과정

### 3.1 데이터 전처리의 문제점

데이터 전처리 과정에서 가장 큰 어려움은 SpellChecker의 예상치 못한 동작이었습니다. 대부분의 단어가 'i'로 변환되는 현상이 발생했고, 이는 전체 문맥을 훼손시키는 심각한 문제였습니다. 이를 해결하기 위해 정규식을 활용한 후처리를 시도했지만, 문맥의 연결성이 떨어지는 새로운 문제가 발생했습니다.

또한 API 호출 기반의 전처리 방식은 속도와 비용 측면에서 비효율적이었습니다. 이를 해결하기 위해 로컬 처리 방식으로 전환하고 ThreadPoolExecutor를 활용한 병렬 처리를 구현했습니다. 이를 통해 처리 속도를 크게 개선할 수 있었습니다.

### 3.2 모델 학습 과정의 문제

초기에는 베이스라인 모델로 48.1088점이라는 높은 점수를 얻었지만, 이후의 모든 시도가 이 점수를 넘지 못하는 상황이 발생했습니다. 이는 오히려 다양한 실험을 시도하게 만드는 동기가 되었습니다.

특히 PPO 알고리즘 구현 과정에서 텐서 크기 불일치와 GPU 메모리 관리 문제가 발생했습니다. 이를 해결하기 위해 다음과 같은 조치를 취했습니다:

1. 배치 크기 최적화 (32 → 16)
2. Gradient Accumulation Steps 도입
3. Mixed Precision (FP16) 사용
4. Gradient Checkpointing 활성화

### 3.3 프롬프트 엔지니어링의 발전

프롬프트 엔지니어링은 점진적으로 발전시켜 나갔습니다:

1. 초기: 단순한 "요약해줘" 형태
2. 개선: 객관적 문어체 사용
3. 발전: 단계별 조건 제시
4. 최적화: temperature와 top_p 값 조정

멘토님의 조언으로 temperature와 top_p 값을 낮추는 시도를 했고, 이는 성능 향상으로 이어졌습니다. 특히 temperature=0.1, top_p=0.2 설정이 가장 좋은 결과를 보였습니다.

## 7. 결론

이번 NLP 경진대회는 개인적으로 매우 의미있는 학습 경험이었습니다. 특히 혼자서 진행하면서 겪은 다양한 시행착오와 그 해결 과정은 깊이 있는 기술적 이해를 가능하게 했습니다.

초기 베이스라인 모델의 높은 성능(48.1088)은 오히려 더 다양한 실험과 도전을 하게 만드는 동기가 되었고, 이는 결과적으로 프롬프트 엔지니어링과 PPO 알고리즘 등 새로운 기술을 탐구하는 기회가 되었습니다.

비록 초기 베이스라인의 점수를 뛰어넘지는 못했지만, 이 과정에서 얻은 기술적 통찰과 문제 해결 경험은 앞으로의 NLP 프로젝트에서 큰 자산이 될 것입니다. 특히 데이터 전처리, 프롬프트 엔지니어링, 강화학습 적용 등의 경험은 실제 프로덕션 환경에서도 유용하게 활용될 수 있을 것입니다.

앞으로도 이러한 경험을 바탕으로 자연어 처리 분야에서 더 깊이 있는 연구와 개발을 진행하고자 합니다. 특히 강화학습과 프롬프트 엔지니어링의 결합, 효율적인 데이터 처리 파이프라인 구축 등에 대해 추가적인 연구를 진행할 계획입니다.
